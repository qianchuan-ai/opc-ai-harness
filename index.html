dsh-at-file0.6.2 装 · 真测

@ 引用文件/目录直接进上下文。写评论、调素材时把本地文件拖进对话，省掉一堆复制粘贴。我每天高频用。

图 实测截图待补 · 真装证据陆续补上
适合谁要喂本地文件/素材给 AI 的一人公司；写长文、做竞品拆解的人
不适合纯云端对话、不需要引用本地文件的人
# 安装 dsh plugin add dsh-at-file
注意 Windows 沙箱下 pnpm safe-delete 会报 trash aborted，清空 CODEBUDDY_SESSION_ID 可解
你装过？踩坑来提 Issue，一起把实测做准 ↗
AI 深度评测 展开分析 ▼
核心价值
表面是「文件引用」，实质是把你的本地工作区变成 AI 的可寻址记忆。价值不在"能读文件"，而在"不用再手动搬运"——长文写作时素材随手 @，竞品拆解时截图/表格直接拖入，上下文连续性远高于复制粘贴。
使用场景写长文时引用本地草稿/素材；做竞品拆解拖入截图与表格；调试时快速验证文件内容是否正确被读取。
真实风险大文件（>50MB）索引慢；Windows 沙箱下卸载会报 trash aborted（清空 CODEBUDDY_SESSION_ID 可解）。纯网页内容场景用 deepread 更顺。
dsh plugin add dsh-at-file

本想省 API、控成本，结果实测切换有延迟、规划质量不稳定。宣传吹得猛，真用起来鸡肋。新手别被带偏。

仅适合已经清楚自己要双模型路由、能容忍延迟的老手
新手别碰为了「省钱」装的，反而更费事

AI 深度评测 展开分析 ▼
核心价值
定位是"双模型路由省 API 成本"——小模型做规划、大模型做执行。概念优雅，但 rc 阶段实测切换有延迟、规划质量抖动，省下的 token 钱远抵不过你反复重跑的时间。
使用场景已明确要精细控 API 成本、且能容忍偶尔延迟波动的团队；长链任务想拆规划/执行两层。
真实风险rc 阶段破坏性变更频繁，规划质量不稳定；新手被"省钱"噱头带偏反而更费事。建议等 v1 稳定。
dsh plugin add dsh-plan-execute
