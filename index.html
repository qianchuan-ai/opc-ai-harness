为什么是现在

商业环境正在剧烈重构：一人公司 / 小团队会越来越依赖 AI 生产力，去扛原本需要三五个人才能做的活。

这不是赌某个工具的红火，而是押一条长期曲线——当人力贵、试错频、身兼多职成为常态，能把「本要自己磨但没空做的 grind」交给 AI 的人，才有弹性产能。

dsh（及同类「一切皆插件」的 harness）只是当前最顺手的载体。趋势没改，它就不过时；它哪天被更好的取代，策展的判断力仍在。

热点皆过客，道是归处——本库策展的「道」，是 OPC 主理人怎么用 AI 插件把产能撑起来。

它是什么 / 不是什么

✅ 是

  • 按 OPC 主理人真实使用场景分类的 dsh 插件策展
  • 每个都我亲测 dsh plugin add 装通过，附真实坑
  • 带场景、带批注、带「适合谁」的精选，不是罗列

❌ 不是

  • 桌面壳 / 全量插件黄页 / 通用市场
  • 「我替你配好」的付费服务
  • 不承诺「获客 / 变现」等结果——工具不创造需求

通用中文壳已有人免费做了。我做的是它不屑做的那层：替你先踩安装坑，把「能装起来」变成可复制的步骤。

真实踩过的坑

这些是所有 dsh plugin add 都会撞的，先读能省一大截。

01
Windows / WorkBuddy 环境专属：底层 pnpm 的「安全删除」调系统回收站被拦截，报 trash operation aborted 直接挂。
→ 修复：用空 CODEBUDDY_SESSION_ID= 跑安装命令，pnpm 回归原生删除（删的都是自身临时暂存目录，安全）：
CODEBUDDY_SESSION_ID= npx -y @deepseek-ai/dsh plugin --profile web add <owner/repo>
（你本机若不走 WorkBuddy 终端，一般不会撞这个，照常装即可。）
02
缺 pnpm：Developer Preview 文档没强调，但 dsh plugin add 依赖 pnpm。先 npm i -g pnpm。
03
GitHub HEAD 偶发 ECONNRESET / ETIMEDOUT：网络抖动，pnpm 自动重试，不用管。
04
首装 compose 重：首次拉全量 profile 依赖可能 1–3 分钟，别当卡死。
